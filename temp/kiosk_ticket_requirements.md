# 키오스크 환경 맞춤형 티켓 발권 시스템 요구사항 정의서

## 1. 개요 (Overview)
현재 결제 완료 후 시스템에서 기본 인쇄창(Print Dialog)이 즉시 호출되는 로직을 변경하여, 키오스크(Kiosk) 기기에 적합한 사용자 경험(UX)을 제공합니다. 사용자가 티켓 정보를 먼저 확인한 후, 직접 '발권하기' 버튼을 눌러 인쇄할 수 있도록 흐름을 개선합니다.

## 2. 현재 상태 (As-Is)
* 결제 모듈에서 결제 성공 시, 즉각적으로 브라우저의 인쇄창(`window.print()` 등)이 호출됨.
* 키오스크 환경에서는 화면 흐름이 끊기거나 사용자가 인쇄 내용을 확인하기 전에 출력이 진행되는 문제가 있음.

## 3. 개선 후 기대 모델 (To-Be)
* 결제 완료 시 인쇄창 대신 **티켓 정보를 담은 '새 창(팝업 또는 새 탭)'**이 열림.
* 새 창 하단에 **[발권하기]** 버튼이 명시적으로 노출됨.
* 사용자가 버튼을 클릭해야만 실제 인쇄(발권) 작업이 진행됨.

## 4. 상세 요구사항 (Detailed Requirements)

### 4.1. 결제 완료 후 프로세스 변경
* 기존: 결제 성공 -> 인쇄창 강제 호출
* 변경: 결제 성공 -> 발권 전용 새 창(웹페이지) 오픈
* 새 창을 열 때 결제 완료된 티켓 데이터(좌석 번호, 결제 금액, 주문 번호 등)를 함께 전달해야 함 (SessionStorage 또는 URL 파라미터 방식 활용).

### 4.2. 발권 전용 새 창 UI/UX 설계
* **화면 구성**: 키오스크 세로 화면 또는 가로 화면에 맞춘 UI 렌더링.
* **티켓 정보 표시**: 행사명, 일시, 선택한 좌석, QR/바코드, 결제 완료 내역 등을 시각적으로 구성.
* **[발권하기] 버튼**: 
  * 화면 최하단(Bottom Fixed)에 크고 터치하기 쉬운 형태로 배치.
  * 직관적인 색상과 디자인 적용.

### 4.3. 발권 동작 및 사후 처리
* 사용자가 **[발권하기]** 버튼을 클릭하면 실제 인쇄 명령(`window.print()`)이 실행되거나, 연결된 키오스크 하드웨어 프린터 모듈이 작동.
* 발권(인쇄 대기열 등록) 완료 후:
  * 예) "발권이 완료되었습니다. 티켓을 수령해 주세요." 형태의 안내 메시지 출력.
  * 일정 시간 후 새 창이 자동으로 닫히고, 기존 시스템(부모 창)은 초기 화면으로 돌아가도록 처리.

## 5. 작업 대상(예상) 파일
* `ui.js` 또는 기존 결제 성공 콜백이 위치한 JS 파일 (인쇄 로직 제거 및 새 창 오픈 로직 추가)
* `ticket_kiosk_view.html` (새로 생성할 발권 확인 전용 페이지)
* 관련 스타일시트(CSS) 및 스크립트(JS)
